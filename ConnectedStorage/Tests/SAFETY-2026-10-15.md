# Item safety audit — in progress

## Hardening

- Cursor requests validate and execute synchronously on the server rather than validating an identity and then queuing a potentially stale slot operation.
- Network mutations defer when native inventory changes for the player or affected units are pending.
- Transfers do not merge different auxiliary-data identities. Native movement can otherwise replace destination metadata.
- Buffer references are reacquired after command-buffer playback.
- Node removal evacuates through the same bounded native transfer operation. Remaining items are left for vanilla drops, including auxiliary data. Locked contents are not stranded in a destroyed node.
- Upgrade validation includes pending player operations before consuming a gem.

## Automated evidence

`Dev/check.py` passes compilation and bundle checks. `test_inventory_safety.py` extracts shipping sort/cursor/transfer methods into a deterministic adapter. It checks 1,000 randomized two-node sorts, locks, variants, auxiliary identities, 9,999-stack overflow, cursor amounts, partial/full destinations and occupied evacuation. This replaces the obsolete pure removal-planner test.

These tests do not simulate Unity ECS lifetimes, native drops, saves or multiplayer replication.

## Live solo evidence

Test character, Test world, 0.7.32-dev; loaded version confirmed in Player.log.

- Existing network reopened with 54 occupied slots / 240 capacity.
- Deposited dirt into a chosen empty slot; occupancy increased to 55.
- Right-click withdrew one dirt; placed that item in another empty slot, occupancy 56. Sort merged the split stack and returned occupancy to 55.
- Left-click native quick-stack button issued the storage command.
- Withdrew a copper pickaxe to the player inventory (54 occupied stacks remain), then mined the occupied Tin node with the Test character's existing Soul Seeker. Network remained at 54 occupied stacks and capacity fell from 240 to 200; the Tin node appeared in the bag. Visible copper bars (24), bucket stack (3), and star stack (3) remained. This is the spare-capacity removal case, not the full-capacity drop case.
- Saved, exited normally, restarted into 0.7.33-dev and reopened Test. The network retained 54 occupied slots / 200 capacity, the same visible stack counts, and the recovered Tin unit in the bag.
- **Found:** right-click deposit-bag did not issue a command and tooltip remained vanilla. The 0.7.33-dev field-reference fix did not resolve it. 0.7.34-dev also identifies buttons by their serialized native quick-stack action and owning player inventory; retest pending.

## Release gates still open

Occupied upgrades, destruction with spare/full capacity, disconnected bridge removal, save/reload totals and auxiliary attributes, full player inventory, repeated rapid inputs, and second-player concurrency require live verification. Performance captures must cover idle, active and removal stress paths; synchronous evacuation is not a measured performance improvement. UI diagnostics must be excluded/disabled for release. Overhaul requires a combined datablock bundle and its own load test. No release-readiness or zero-item-loss claim yet.
